For an enterprise-grade Azure Functions (.NET Isolated Worker) solution, I would strongly recommend a **Vertical Slice Architecture** rather than grouping by technical layers. This aligns perfectly with your requirements:

I wanted to create a function app with different serivces as each functions  (dotnet isolated worker model + all open source libraries)
Each function should have seperate schema to be validated
Each Function should have seperate folder in the project structure
Each Function should have downstream processing 
Each downstream processing  should have following logic
  Log the call is starting
  Parse Function request payload to Service Request Mapper (Request mapper is a soap request mapper and Soap model is generated from wsdl using Microsoft.Tools.ServiceModel.Svcutil)
  Call APIM using soap request
  Get Soap Response from APIM
  Parse Soap Respose to Function Response and return response
  Log the call is successful or error base on the response
  Write to Cosmos db transaction Audit

# Cosmos Repository

```csharp
public interface IAuditRepository
{
    Task SaveAsync(AuditDocument document);
}
```

```csharp
public class AuditRepository
    : IAuditRepository
{
    private readonly Container _container;

    public AuditRepository(CosmosClient client)
    {
        _container = client.GetContainer(
            "AuditDb",
            "Transactions");
    }

    public async Task SaveAsync(
        AuditDocument document)
    {
        await _container.CreateItemAsync(
            document,
            new PartitionKey(document.ServiceName));
    }
}
```

# Service Handler

All business logic stays here.

```csharp
public class CustomerLookupHandler
{
    private readonly ILogger<CustomerLookupHandler> _logger;

    private readonly ISoapClient _soapClient;

    private readonly IAuditRepository _auditRepository;

    public CustomerLookupHandler(
        ILogger<CustomerLookupHandler> logger,
        ISoapClient soapClient,
        IAuditRepository auditRepository)
    {
        _logger = logger;
        _soapClient = soapClient;
        _auditRepository = auditRepository;
    }

    public async Task<CustomerLookupResponse> Handle(
        CustomerLookupRequest request)
    {
        _logger.LogInformation(
            "CustomerLookup Started");

        var soapRequest =
            new CustomerLookupRequestMapper()
                .Map(request);

        var soapResponse =
            await _soapClient
                .CustomerLookupAsync(
                    soapRequest);

        var response =
            new CustomerLookupResponseMapper()
                .Map(soapResponse);

        await _auditRepository.SaveAsync(
            new AuditDocument
            {
                id = Guid.NewGuid().ToString(),
                ServiceName = "CustomerLookup",
                Request =
                    JsonSerializer.Serialize(request),
                Response =
                    JsonSerializer.Serialize(response),
                Success = true,
                CreatedDate = DateTime.UtcNow
            });

        _logger.LogInformation(
            "CustomerLookup Completed");

        return response;
    }
}
```

# Azure Function

```csharp
public class CustomerLookupFunction
{
    private readonly CustomerLookupHandler _handler;

    public CustomerLookupFunction(
        CustomerLookupHandler handler)
    {
        _handler = handler;
    }

    [Function("CustomerLookup")]
    public async Task<HttpResponseData> Run(
        [HttpTrigger(
            AuthorizationLevel.Function,
            "post")]
        HttpRequestData req)
    {
        var request =
            await req.ReadFromJsonAsync
                <CustomerLookupRequest>();

        var response =
            await _handler.Handle(request);

        var httpResponse =
            req.CreateResponse(
                HttpStatusCode.OK);

        await httpResponse
            .WriteAsJsonAsync(response);

        return httpResponse;
    }
}
```

# Dependency Injection

Program.cs

```csharp
var host = new HostBuilder()
    .ConfigureFunctionsWorkerDefaults()
    .ConfigureServices(services =>
    {
        services.AddSingleton<
            ISoapClient,
            SoapStubClient>();

        services.AddSingleton<
            IAuditRepository,
            AuditRepository>();

        services.AddScoped<
            CustomerLookupHandler>();

        services.AddValidatorsFromAssemblyContaining
            <CustomerLookupValidator>();
    })
    .Build();

host.Run();
```

For a production enterprise implementation, I would add:



* MediatR pipeline behavior
* FluentValidation pipeline
* Correlation Id middleware
* OpenTelemetry tracing
* Polly retry/circuit breaker
* APIM SOAP client wrapper using HttpClientFactory
* Centralized audit pipeline
* Serilog + Application Insights
* Options Pattern for APIM endpoints
* Unit of Work for Cosmos writes
* Contract testing for SOAP schemas
* CI/CD with Azure DevOps or GitHub Actions
* Separate Function App project and Domain/Application/Infrastructure class libraries (Clean Architecture)

That would be the pattern typically used for 20–100+ SOAP-backed functions in a large enterprise Azure Function App.
