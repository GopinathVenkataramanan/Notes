Here’s a **comprehensive upgrade plan** for upgrading **IBM WebSphere Application Server Network Deployment (WAS ND) from 8.5.5 to 9.0.5.x**, including **nuances and challenges**, especially given that you also run **BAW (Business Automation Workflow), ODM (Operational Decision Manager), and DX (Digital Experience/Portal)** on the WAS environment.

---

## 📌 1. **Pre-Upgrade Assessment**

### 🧠 1.1 Inventory & Discovery

Document:

* All WAS ND cells, nodes, clusters
* OS versions & patch levels
* JVM versions
* Heap/performance settings
* Installed feature packs/fixes
* Applications deployed (BAW, ODM, DX etc.)
* Integration points (LDAP, SSO, MQ, DBs)

⚠️ **Nuances:**

* WAS 9 uses **Java 8 and can optionally support Java 11** (depending on your fixpack). WAS 8.5.5 often runs Java 6/7/8.
* Some applications may require higher Java versions—test compatibility first.

---

## 📌 2. **Compatibility & Support Matrix**

### 🧠 2.1 IBM Support Guidance

Validate compatibility for:

* **BAW 19.x/18.x**
* **ODM 8.x**
* **IBM DX/Portal versions**

Each of these products certified with specific WAS versions.

⚠️ **Challenges:**

* Unsupported combinations will break integrations.
* Must align fix pack levels: IBM often requires minimum WAS 9 fix pack for BAW/ODM to be supported.

---

## 📌 3. **Hardware & OS Compatibility**

Ensure:

* OS level is supported for WAS 9
* Kernel limits, ulimits, and filesystem permissions align

⚠️ **Nuances:**

* WAS 9 stopped support for some old OS versions.
* E.g. older AIX, Solaris releases, or RHEL/CentOS legacy kernels.

---

## 📌 4. **Upgrade Strategy Decision**

### 🔁 Options

1. **In-Place Upgrade**

   * Upgrade existing servers
   * Riskier on production
2. **Side-By-Side Installation**

   * Install WAS 9 alongside WAS 8.5.5
   * Migrate configurations & applications
   * **Preferred safest approach**
3. **Blue/Green Cutover**

   * Deploy new environment parallel
   * Shift traffic after validation

💡 Best Practice: **Side-by-side + config migration**

---

## 🛠 5. **Detailed Upgrade Steps (Side-by-Side)**

### 5.1 Install WAS 9.0.5.x

* Install binaries on all nodes
* Same cell topology
* Validate OS prerequisites

### 5.2 Install Fix Packs

* Install latest 9.0.5.x fix packs on all nodes
* Apply same FP level across dmgr & nodes

### 5.3 Migrate Profiles

For each node:

```bash
<WAS_HOME>/bin/manageprofiles.sh -createNewProfileFromTemplate
```

### 5.4 Migrate Cell Configuration

Use **WAS Migration Tool**:

```bash
WAS_HOME/bin/WASPreUpgrade.sh
WAS_HOME/bin/WASUpgrade.sh
```

### 5.5 Validate Config

Check:

* Nodeagent logs
* Admin console access

---

## 📌 6. **Application Migration**

### 6.1 BAW

* Export BAW EAR files
* Update datasource/JDBC configs
* Reconfigure integrations (BIRT, BPM)

### 6.2 ODM

* Migrate rulesets
* Update decision server configs

### 6.3 DX (Portal)

* Redeploy DX apps
* Test themes, web modules
* Reconfigure LTPA tokens

⚠️ **Challenges:**

* Java version dependency changes
* LDAP & SSO changes between WAS versions
* JMS and MQ resource reconfiguration

---

## 📌 7. **Libs & JVM Custom Settings**

### 7.1 JVM Parameters

* Compare 8.5.5 JVM options
* Retain heap, GC, system props
* Evaluate need for **IBM J9 vs OpenJ9**

### 7.2 Shared Libraries

* Reattach into WAS 9
* Validate classloaders

---

## 📌 8. **Security & Certificates**

* WAS 9 may enforce stricter protocols (TLS 1.2/1.3)
* Update:

  * SSL configs
  * KeyStore trust
  * LDAP SSL
* Validate LTPA token version

⚠️ **Nuances:**

* SSL ciphers default may change
* Partners/integrations may break if TLS versions misaligned

---

## 📌 9. **Connectivity & Integration Points**

### 9.1 LDAP/SSO

* Validate login from external identity store
* Ensure federation trusted

### 9.2 MQ/JMS

* Recreate MQ connection factories
* Test JMS messaging

### 9.3 Databases

* Test DB connectivity
* Validate drivers compatibility

---

## 📌 10. **Testing Plan (Major)**

### 🔹 Smoke Tests

* Start dmgr, nodeagents, servers
* Access admin console

### 🔹 Functional Tests

* BAW workflows
* Rule execution in ODM
* DX portal pages

### 🔹 Performance Tests

* Load testing peak traffic scenarios
* Compare to baseline

### 🔹 Security Scans

* Pen test, vulnerability scan

⚠️ **Pitfall:**
Lack of adequate testing often causes post-go-live issues.

---

## 📌 11. **Rollback / Contingency Plan**

### 🛡 Rollback Options

* Restore old WAS 8.5.5 environment (side-by-side allows this)
* Restore database snapshots

### 🧯 Risks if Rollback Needed

* Rule changes
* Workflow state corruption
* User sessions lost

---

## 📌 12. **Cutover & Go-Live**

### 🗓 Pre-Cutover

* Freeze deployments
* Reverify configurations

### 🟢 Go-Live

* Switch DNS/load-balancer
* Monitor logs

---

## 📌 13. **Post-Upgrade Monitoring**

* Collect logs:

  * SystemOut.log
  * SystemErr.log
* Setup alerting for:

  * GC pauses
  * Thread deadlocks
  * High memory usage

## 🚩 Known Challenges / Nuances

| Area           | Nuances / Risks                                     |
| -------------- | --------------------------------------------------- |
| Java Version   | Some apps need Java 8 → WAS9 supports Java 8 or 11  |
| SSL/TLS        | Stricter default protocols                          |
| LDAP/SSO       | LTPA token renewals can break                       |
| MQ             | Recreating resources with correct attributes        |
| ODM/BAW        | Must match certified fix pack matrix                |
| Port Conflicts | Ensure new WAS install ports don’t overlap old ones |
| Performance    | JVM GC behaviors differ between versions            |
| Scripts        | Custom wsadmin scripts may need syntax changes      |
